## 计算机内数据的表示（定点数 vs 浮点数）
```
定点数：
小数点固定
→ 定点整数
→ 定点小数
→ 常考原码、反码、补码、移码、范围

浮点数：
N = M × R^E

M：尾数 → 决定精度
E：阶码 → 决定范围

阶码越长 → 范围越大
尾数越长 → 精度越高

浮点数常考：
① 表示形式
② 阶码和尾数作用
③ 规格化
④ 表示范围
⑤ 精度
⑥ 溢出
```
## 计算机内数据的表示（校验码）
**奇偶校验码**
```
奇偶校验码基本思想是：通过在编码中增加一位校验位来是编码中1的个数为为奇数（奇校验）或者为偶数（偶校验），从而使码距变为2.对于奇校验，它可以检测代码中奇数位出错的编码，但不能发现偶数位出错的情况，即当合法编码中奇数位发生了错误，也就是编码中的1变成0或者0变成1，则该编码中1的个数的就行就发生了变化，从而可以发现错误。
```
**循环冗余校验码**
```
循环冗余校验码（CRC）广泛应用与数据通信领域和磁介质存储系统中。他利用生成多项式为K个数据位产生r个校验位来进行编码，其编码长度位k+r
```
**海明码**
```
海明码的构成方法是：在数据位之间插入k个校验码，通过扩大码距来实现检错和纠错

设数据位位n位，校验位位k位，则n和k必须满足一下关系
2^k >= k + n + 1

例如：已知数据信息为16位，最少应加多少位校验码，才能实现纠错

k代入3 8  >= 16 + 3 + 1  X
k代入4 16 >= 16 + 4 + 1  X
k代入5 32 >= 16 +5 + 1   √

所得 最少要加入5位校验码
```

### 主存储器

<img width="154" height="219" alt="image" src="https://github.com/user-attachments/assets/8383ac23-07dc-4bed-9a2d-204536cb5f38" />

```
1. 存储元
存储元：存储二进制信息的基本电子元件，每个存储元可以存放 1bit，即一个二进制位 0 或 1。

2. 存储单元
存储单元：由若干个存储元组成，每个存储单元可以存放一串二进制代码。
每个存储单元都有唯一的地址。

3. 存储字（Word）
存储字：一个存储单元中存放的一组二进制代码。

4. 存储字长
存储字长：一个存储单元中二进制代码的位数。
例如：
一个存储单元可以存放 16bit 数据，则存储字长 = 16bit。

5. MAR：地址寄存器
MAR（Memory Address Register）：存放当前要访问的存储单元地址。

MAR 的位数决定可以寻址多少个存储单元。

例如：
MAR = 4 位

可表示地址：
0000 ～ 1111

共有：
2^4 = 16 个地址

所以最多可以寻址 16 个存储单元。

规律：
MAR 为 n 位 → 最多可以寻址 2^n 个存储单元。

6. MDR：数据寄存器
MDR（Memory Data Register）：存放从主存读取的数据，或者准备写入主存的数据。

通常：
MDR 的位数 = 存储字长

例如：
MDR = 16 位
则一次可以读取或写入 16bit 数据，
存储字长通常为 16bit。

7. bit 与 Byte

1 bit = 1 个二进制位

1 Byte（字节） = 8 bit

注意：
1B = 1 Byte = 8bit
1b = 1 bit

B 和 b 含义不同。
```
### CPU-运算器

<img width="113" height="160" alt="image" src="https://github.com/user-attachments/assets/0c1711c1-44e7-4a31-b186-d5666a5d9202" />

```
ACC：累加器（Accumulator）
用于暂存操作数、中间运算结果或最终运算结果。
很多算术运算和逻辑运算都会默认使用 ACC。

MQ：乘商寄存器（Multiplier-Quotient Register）
主要用于乘法和除法运算。
乘法时可用于存放乘数或乘积的一部分；
除法时可用于存放商。

X：通用操作数寄存器
用于暂存参与运算的操作数。
可作为 ALU 运算的数据来源之一。

ALU：算术逻辑单元（Arithmetic Logic Unit）
负责执行各种算术运算和逻辑运算。

算术运算：
加、减、乘、除等。

逻辑运算：
与（AND）、或（OR）、非（NOT）、异或（XOR）等。

ALU 是运算器的核心部件。

DR：数据寄存器 / 数据缓冲寄存器（Data Register）
用于暂存 CPU 与存储器之间传送的数据。

例如：
从存储器读取的数据，可以先放入 DR；
准备写入存储器的数据，也可以先放入 DR。

有些教材中 DR 和 MDR 的作用基本相同。
PSW：程序状态字寄存器（Program Status Word）
用于保存 CPU 当前运行状态以及运算产生的各种标志位。

常见标志：
CF：进位标志
ZF：零标志
SF：符号标志
OF：溢出标志
```

### CPU-控制器

<img width="141" height="217" alt="image" src="https://github.com/user-attachments/assets/5891b352-797e-4fb2-b3d0-0e0c0cafdd95" />

```
CU：控制单元（Control Unit）
负责分析和控制指令的执行过程，根据指令产生相应的控制信号，
协调运算器、存储器、输入/输出设备等部件工作。

IR：指令寄存器（Instruction Register）
用于存放当前正在执行的指令。

CPU 从内存取出的指令会先送入 IR，
再由指令译码器对其中的操作码进行分析。
PC：程序计数器（Program Counter）
用于存放下一条将要执行的指令地址。

一般情况下，每取完一条指令，PC 会自动加 1
（更准确地说，是自动更新到下一条指令地址）。

如果遇到跳转、分支等指令，
PC 会被修改为新的目标地址。
AR：地址寄存器（Address Register）
用于保存当前 CPU 要访问的存储单元地址。

CPU 读取或写入内存时，
需要先把目标地址送入 AR。

很多教材中：
AR ≈ MAR（存储器地址寄存器）
ID：指令译码器（Instruction Decoder）
用于对指令中的操作码进行译码和分析，
判断该指令要完成什么操作。

例如：
ADD → 加法
SUB → 减法
LOAD → 读取数据
JMP → 跳转
```

### 指令系统
**指令格式**
```

1. 指令的概念
一条指令就是机器语言中的一条命令，
本质上是一组具有特定含义的二进制代码。

2. 指令的基本组成
一条指令通常由两部分组成：

操作码（OP） + 地址码（A）

操作码 OP：
说明“要做什么操作”。

例如：
ADD   加法
SUB   减法
LOAD  读取数据
STORE 保存数据
JMP   跳转

地址码 A：
说明“对谁进行操作”，
即指出操作数的位置或操作数本身。
```
**寻址方式**
| 寻址方式 | 操作数/地址在哪里 | 核心公式 |
|---|---|---|
| 立即寻址 | 指令中直接存放操作数 | 操作数 = A |
| 直接寻址 | A 就是操作数所在的内存地址 | EA = A |
| 间接寻址 | A 指向的内存单元中存放真正地址 | EA = (A) |
| 寄存器寻址 | 操作数存放在寄存器中 | 操作数 = (R) |
| 寄存器间接寻址 | 寄存器中存放操作数的内存地址 | EA = (R) |
| 变址寻址 | 地址码 A 与变址寄存器 IX 相加得到有效地址 | EA = A + (IX) |
| 相对寻址 | PC 与偏移量 A 相加得到有效地址 | EA = (PC) + A |
**复杂指令集计算机-CISC vs 精简指令集计算机-RISC**
```
CISC：
多、复杂、不定长、多寻址、微程序、流水难。

RISC：
少、简单、定长、少寻址、多寄存器、Load/Store、硬布线、流水强。
```
**指令的流水处理**

<img width="346" height="212" alt="image" src="https://github.com/user-attachments/assets/17b62f73-d540-4e43-a008-a9117fa08dbf" />

**指令流水的计算**
```
例如：若指令流水线把一条指令分为取指、分析和执行三部分，且三部分的时间分别是取指2ns，分析2ns，执行1ns，那么流水线周期是多少？100条指令全部执行完毕需要多长时间？

流水线周期为执行时间最长的一段
流水线计算公式：1条指令执行时间 + （指令条数 - 1）*流水线周期

2 + 2 + 1 + （100 - 1）* 2 = 198 + 5 = 203
```
**流水线吞吐率的计算**
```
流水线的吞吐率：是指在单位时间内流水线所完成的任务数量或输出的结果数量。计算流水线吞吐率的最基本的公式：

TP = 指令条数 / 流水线执行时间

例如上题 TP = 100 / 203 ≈ 0.4926 条/ns
```
**流水线加速比的计算**
```
完成同样一批任务，不适用流水线所用的时间与使用流水线所用的时间之比称为流水线加速比。计算公式如下：

S = 不使用流水线执行时间 / 使用流水线执行时间

例如上题 S = 500 / 203 ≈ 2.463
```
### 输入输出技术、CPU与外设之间的数据传递方式
```
CPU 与外设之间常见的数据传递方式主要有：

1. 程序查询方式
2. 中断方式
3. DMA 方式
4. 通道方式
```
```
1. 程序查询方式

CPU 主动不断查询外设状态，
判断外设是否已经准备好。

工作过程：

CPU 查询外设状态
→ 未准备好：继续查询
→ 已准备好：进行数据传输

特点：
- 实现简单
- CPU 和外设串行工作
- CPU 需要一直等待、查询外设
- CPU 利用率低

记忆：
CPU 一直问：“你好了吗？你好了吗？”
```
```
2. 中断方式

CPU 不需要一直等待外设。

外设准备好后，
主动向 CPU 发出中断请求，
CPU 暂停当前程序，执行中断处理程序，
完成数据传输后再返回原程序继续执行。

工作过程：

CPU 执行其他程序
→ 外设准备完成
→ 外设发出中断请求
→ CPU 响应中断
→ 执行中断服务程序
→ 返回原程序

特点：
- CPU 与外设可以并行工作
- CPU 利用率比程序查询方式高
- 每次数据传输通常仍需要 CPU 参与

记忆：
外设准备好了以后主动“喊 CPU”。
```
```
3. DMA 方式

DMA（Direct Memory Access）
直接存储器访问。

数据可以在外设和主存之间直接传输，
不需要 CPU 一次一次参与数据搬运。

工作过程：

CPU 设置 DMA 参数
→ DMA 控制器取得总线控制权
→ 外设和主存直接传输数据
→ 传输完成
→ DMA 通知 CPU

特点：
- 数据直接在外设和主存之间传输
- CPU 只负责初始化和结束处理
- CPU 干预少
- 传输速度快
- 适合大量、高速数据传输

例如：
磁盘、网卡等高速设备的数据传输。

记忆：
DMA 帮 CPU “搬数据”。
```
```
4. 通道方式

通道是一种具有一定处理能力的专用 I/O 处理器。

CPU 只需要告诉通道：
“要完成什么 I/O 操作”。

然后由通道独立负责：
- 控制外设
- 执行 I/O 指令
- 管理数据传输

特点：
- CPU 干预最少
- 通道可以执行通道程序
- 可以管理多个外设
- I/O 处理能力强
- 常用于大型计算机系统

记忆：
通道相当于专门负责 I/O 的“小 CPU”。
```
